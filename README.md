# CleanLink

Сервис поиска и бронирования уборки для дома и офиса. Клиент выбирает услугу, площадь, дополнительные работы и свободное время. Сервер рассчитывает стоимость и сохраняет заказ в PostgreSQL. Исполнитель подтверждает и завершает заказ; клиент оставляет отзыв.

## Команда

- Жақсылық Әлихан — разработка и продукт: сервер, авторизация, заказы, база данных и запуск.
- Анаш Ақдаулет — дизайн и фронтенд: страницы, каталог, мобильный интерфейс и избранное.
- Ербосынова Лаура — поддержка и работа с клинерами: отзывы, уведомления и инструкции.

## Возможности

- Регистрация клиента и мастера, кабинет администратора и проверка мастеров.
- Каталог с фильтрами; расчёт стоимости на сервере; проверка пересечений заказов.
- Отзывы после выполненной уборки и уведомления об изменениях заказа.
- Голубой адаптивный дизайн и избранные услуги. Сердечко сохраняет услугу в этом браузере без регистрации; повторное нажатие удаляет её.
- Оплата наличными исполнителю после уборки. Приёма банковских карт нет.

## Деплой на Render

Публичная ссылка будет добавлена после успешного запуска и проверки. Сейчас наличие репозитория само по себе не означает, что сайт опубликован.

1. В Render выберите **New → Blueprint** и подключите этот репозиторий, ветку `main`.
2. Render прочитает `render.yaml`: он описывает Node.js Web Service и отдельную PostgreSQL.
3. Проверьте, что оба ресурса используют план **Free**, если нужен бесплатный запуск.
4. Задайте `ADMIN_EMAIL` и **новый уникальный** `ADMIN_PASSWORD` длиной не менее 12 символов. Не используйте ранее опубликованные тестовые пароли. `JWT_SECRET` создаётся автоматически, `DATABASE_URL` берётся из новой облачной базы.
5. Запустите Blueprint. Сборка: `npm ci`. Старт: `npm run db:init && npm start`. Инициализация создаёт таблицы и применяет миграцию; `db:reset` для деплоя не нужен.
6. Откройте выданный Render адрес, затем `/api/health`. Ожидаемый ответ: `{"status":"ok","db":"up"}`.
7. Зарегистрируйте мастера, войдите администратором и подтвердите его профиль. Мастер добавляет услугу. Зарегистрируйте клиента и оформите заказ, чтобы проверить сохранение данных после обновления страницы.

На облачном сайте отдельная база. Локальные аккаунты и заказы автоматически не переносятся. `SEED_DEMO=false`: каталог изначально пустой. Сервер слушает `0.0.0.0` и порт из окружения Render. Веб-сервер отдаёт и интерфейс, и API; отдельный Static Site не требуется.

По [документации Render](https://render.com/docs/free), бесплатный сервер засыпает после 15 минут без запросов, а бесплатная PostgreSQL истекает через 30 дней. Перед защитой откройте сайт заранее. Для более долгого хранения базы заранее выберите подходящий план или перенесите данные.

## Локальный запуск

Нужны Node.js 18+ и PostgreSQL 14+.

```powershell
npm ci
Copy-Item .env.example .env
# Заполните DATABASE_URL, JWT_SECRET и данные администратора в .env.
npm run db:init
npm start
```

По умолчанию адрес — `http://127.0.0.1:3000`; фактический порт задаёт `PORT`. Не выполняйте копирование шаблона поверх уже настроенного `.env`.

## Проверки

```powershell
npm test
node test/favorites.mjs
```

Серверные проверки используют отдельную временную схему PostgreSQL; нужны подключение к тестовой базе и права создания схем. Проверки избранного не требуют базы данных.

## Данные и безопасность

`.env` не должен попадать в GitHub. В репозитории хранится только `.env.example` с примером настроек. Секреты для Render задаются в Environment.

Если секрет был опубликован, удаление файла из новой версии не удаляет старые коммиты. Нужно заменить пароль базы, пароль администратора и секрет JWT в соответствующих системах. Изменение `ADMIN_PASSWORD` в окружении не сбрасывает пароль уже существующего администратора: инициализация создаёт его только при отсутствии записи.

Пароли хэшируются bcrypt; SQL-запросы параметризованы. Авторизация использует HttpOnly cookie и CSRF-токен, роли проверяются сервером. В production cookie передаётся только по HTTPS. CSP включена. Избранное хранится отдельно в localStorage и не содержит паролей.
